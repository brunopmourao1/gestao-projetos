## Sessão 2026-08-13 — Auditoria de segurança completa + correções (HU-23)
Pedido do usuário: "faça uma auditoria de segurança completa no meu projeto", depois "implemente todas as correções necessárias ... quero esse site com nível de segurança profissional, nele possui algumas informações valiosas", depois (mesma sessão) "faça outra auditoria de segurança para verificar o status atual agora". Duas rodadas.

**1ª rodada — auditoria + correções:**
- Revisão estática (código, histórico do git, `npm audit`) identificou: login sem rate limiting, cookie de sessão = `sha256(APP_PASSWORD)` fixo e não-revogável, nenhum header de segurança, comparação de senha não constant-time, open redirect em `?redirect=` no login, rota aninhada de pendência não validando `idProjeto`, e uma dependência (`nanoid`) com CVE *high* transitiva.
- Corrigido tudo: `src/lib/auth.ts` reescrito (token de sessão aleatório de 256 bits + tabela nova `sessoes`; comparação de senha via SHA-256 + `crypto.timingSafeEqual`); rate limiting persistido em Postgres (tabela nova `tentativas_login`, 5/15min, `429 MUITAS_TENTATIVAS`) em `src/app/api/login/route.ts`; `src/app/api/logout/route.ts` passou a revogar a sessão no banco; headers de segurança (CSP, `X-Frame-Options` etc.) em `next.config.ts`; `redirectSeguro()` no login; `and(idPendencia, idProjeto)` na rota aninhada; `npm audit fix` (nanoid).
- 2 tabelas novas aplicadas via `db:push` (mesmo fluxo real do projeto — `db:generate` pede confirmação interativa via TTY que não existe no ambiente do agente).
- Verificado: `tsc`/`npm test` (66/66) limpos, fluxo completo testado via `curl` contra `npm run dev` local (rate limit disparando na 6ª tentativa, sessão revogada após logout etc.). Commitado (`088d912`) e pushado a pedido explícito do usuário.

**2ª rodada — reauditoria pegou uma regressão real:** verificar "de novo" levou a testar de verdade no navegador (não só `curl`), e a CSP da 1ª rodada (`script-src 'self'` sem nonce) estava **quebrando a hidratação do React em produção, em toda página** — o App Router transporta o payload de RSC via `<script>` inline, e sem nonce o browser bloqueia esse script silenciosamente (aparecia só como `Minified React error #412: Connection closed` no console, sem o aviso clássico de violação de CSP). Corrigido movendo a CSP pra `src/proxy.ts` com nonce gerado por request (padrão oficial do Next.js — ver `content-security-policy.md` nos docs bundled), sem custo real porque toda rota já era dinâmica. Reverificado com `next build && next start` (build de produção real) no navegador, local e em produção após o deploy — console limpo, reatividade confirmada. Commitado (`8f81158`) e pushado.
